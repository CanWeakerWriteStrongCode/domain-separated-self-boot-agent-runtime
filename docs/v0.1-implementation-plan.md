# BaijiMind v0.1 实现计划（Java 业务/执行全栈 + Go 转接/沙箱服务）

> 对应开源项目：domain-separated-self-boot-agent-runtime
> 计划版本：v0.1 第一版 · 文档日期：2026-08-21
> 依赖范式白皮书：[docs/original-2026-paradigm.md](original-2026-paradigm.md) · 关键决策记录：[docs/v0.1-key-decisions.md](v0.1-key-decisions.md)

## Context

把白皮书范式落成第一个可运行版本。经多轮确认的最终拆分原则——**凡业内认为某语言不适配的活，一律归到适配的语言**：

- **Java = 业务/治理/知识/编排/执行全栈**：认证/RBAC/组织树/项目需求/配置/内容空间权限/审批/版本/审计/密钥/通知 + 流程编排 + **对话式命令路由（IM @AI 指令→领域动作）** + **RAG**（Spring AI/Tika/Milvus）+ **AI Agent 执行循环 + harness 工具 + Git 操作**（LangChain4j/Spring AI）
- **Go = 转接/沙箱域，只留两样最强项**：**IM 网关（长连接 I/O）** + **插件运行时（WASM 沙箱）**
- 另配套一个**插件能力注册中心（简化 Nacos）**：管理 AI 插件的注册、调用契约、能力路由与运行状态，让系统知道"怎么调、调用谁"

决策依据：RAG 移 Java（Go 无 RAG 生态）；AI Agent 移 Java（agent 生态 Python>TS>Java>Go，且 agent 依赖 Java 域数据，进程内调用省 RPC）；Go 保留的正是业界公认它最强的两项。

**自举的定义（对齐用户愿景）**：AI 在协作执行中自己发现可复用的能力 → 写成**业务级插件**（类比飞书里那堆小服务：事件驱动、订阅业务/IM 事件、自治执行）→ 沙箱内**即写即执行**（自举的自由，边界在沙箱）→ 晋升为对外可用能力时需**审批+版本**（自举的受控）。插件分两种：**工具型**（被 agent 按契约调用）与**业务型/事件驱动**（订阅事件自主运行）。**发现多通道**：即时（agent 协作中主动提议）+ 周期（自举观察器定时组织审计）+ **harness 工具自省**（局部+总体审视，判断是否需要新版本 harness 插件）。

约束：不要太复杂，docker-compose 一键起，最小 Vue3 控制台，AI 统一走 OpenAI 兼容 API。

## 关键流程（含各流程注意点）

**1. 任务闭环**
人（前端/IM）经 Java 创建 `exec_task=CREATED` → Java worker 原子领取（=CLAIMED, owner, claim_at+deadline）→ Agent 进程内取 RAG 上下文 → harness 工具执行（内置原生；AI 新插件经 gRPC `ExecutePlugin` 调 Go 沙箱）→ 产出制品（MinIO）/推 feature 分支 → 置 DONE + 回传总结 → Java 通知（站内 + gRPC `SendMessage` 发飞书）→ 人审批合并。全程 event+audit。
- **注意点**：领取/状态迁移用单行条件 UPDATE（status=?）防并发双领；CLAIMED 带 deadline，超时回收重置，避免死任务；执行幂等可重入（制品覆盖写+唯一键）；全程按授权人作用域（决策12）经内容访问接口读数据（决策14）；git 只推 feature 分支，不碰主分支/生产。

**2. RAG 构建与检索**
Java @Scheduled 增量拉 msg_archive + space_doc → Tika 解析 → 结构化切块 → embedding（OpenAI 兼容 API）→ 写 Milvus（project_id 分区 + 权限元数据）；检索：Milvus 混合检索（dense+BM25+RRF）+ 分区裁剪权限过滤 → top-k → 可选重排 → 拼 context。AI agent 与前端都走同一进程内检索。
- **注意点**：增量用游标/时间戳去重，防重复索引；切块 512-1024 token + 128 overlap，聊天文本按时间窗口切；元数据（项目/需求/权限域）必须带上、检索前过滤；权限过滤在 index 层（分区裁剪），不后置过滤；embedding 模型选定后版本化，换模型需全量重建。

**3. AI 自举审批版本化**
Java agent 提交新插件/新流程 → Java 建 `boot_approval(PENDING)` + 版本草稿（含 contract_schema + event_subscriptions）→ 通知审批人 → approve → gRPC `ActivatePlugin` 下发契约并通知 Go 热加载进 `boot_registry` / 流程版本 ACTIVE → 按 capabilityKey 发现、按契约 function-calling、`ExecutePlugin` 沙箱执行 → 回滚 `DeactivatePlugin` + 重激活旧版本。
- **注意点**：版本状态机（DRAFT/ACTIVE/INACTIVE/REJECTED）单调迁移，禁止跳变；契约与事件订阅随版本不可变；热升级失败自动回退旧版；控制面（boot_plugin_version）与运行态（boot_registry）一致性靠 ListPlugins 对账。

**4. AI 自举闭环（发现→沙箱即写即执行→晋升审批）**
发现（即时 agent 提议 / 周期观察器报告）→ `propose_plugin` 起草 DRAFT → Go 沙箱开发态即写即执行试运行 → 满意提交审批 → approve → `ActivatePlugin` 下发契约+事件订阅 → 运行时开始接收业务/IM 事件自主运行（飞书小服务）→ 产出回 Java 域 → 回滚 `DeactivatePlugin`。
- **注意点**：DRAFT 沙箱只碰沙箱内资源、无凭据（决策14）、不接触生产；"即写即执行"的自由以沙箱边界为限；晋升必须审批+版本；事件订阅命中范围按项目/权限域受限，防插件越权接事件。

**5. harness 工具自省（二期闭环，v0.1 仅留口子）**
agent 调用工具 → 机械信号落 exec_task_event（v0.1）→ 二期周期聚合总体审视 → LLM 判断"某 harness 插件需不需要新版本" → 版本升级提案 → 审批 → 新版本 → `ActivatePlugin` 热升级 → 可回滚。
- **注意点**：v0.1 只落数据口子（重试/错误/耗时 + 预留 tool_feedback 字段），不实现分析；二期直接复用审批/版本管线，无需新机制。

**6. 会话驱动工作流闭环（IM 场景主线）**
管理员建群+绑项目/需求+配机器人+绑流程 → 产品/开发/测试在群里与 AI 协作（消息落内容空间）→ 人 @AI 指令（如"开始写 PRD"）→ 命令路由 LLM 解析 →（决策点）管理端需求流程页审批（群里发链接跳转，类似 OA）→ 推进 → 建 exec_task（授权人=点击者，决策12）入任务队列 → AI 领取并以授权人数据权限执行（写 PRD/gen_h5_prototype 画 H5/写代码）→ 产物入内容空间 → 产品 IDE 改 → 人 @AI"进入下一流程"（或流程页操作）→ 流程引擎推进 → 后续阶段 AI 出设计图 → 明确"写代码" → agent harness 写代码推 feature 分支 → 人 IDE 改推送 → 测试 → 交付通知。全程 im_command/event/audit 落账。
- **注意点**：@AI 指令需二次确认（管理端流程页审批），防误触；授权人=点击者/指令发送者，数据权限全链路贯穿（决策12/14）；意图解析失败降级为"回复提示无法理解"，不静默；群里只发管理端链接，流程决策在管理端完成；im_command 全程落账可追溯。

## 总体架构（docker-compose 拓扑）

```
Browser ──HTTPS──> Nginx(单入口) ──/api──> java-server:8080 (Sa-Token 校验 + 全部业务/编排/执行/RAG)
Feishu ──长连接──> go-server:8090 (IM 网关:收事件+归档+发消息)

java-server: MySQL(几乎全部表) · Redis(Sa-Token/缓存) · MinIO(文档+制品) · SSH密钥(AES-GCM存库)
```

## 关键技术决策

详见 [docs/v0.1-key-decisions.md](v0.1-key-decisions.md)，此处为摘要：

1. **gRPC 动作面（Java→Go，单向小面）**：`SendMessage` / `ExecutePlugin` / `ActivatePlugin` / `DeactivatePlugin` / `ListPlugins` / `SubscribeEvents`，约 5-6 个 RPC。浏览器/飞书/MinIO 全走 HTTP。
2. **数据库 Java 几乎全 owner**：Go 只写 `msg_archive` 与 `boot_registry`，其余全部 Java 管。`deploy/sql/schema.sql` 一份 DDL + 表所有权清单。
3. **任务队列**：`exec_task` 表 + 原子领取乐观锁，`claim_at+deadline` 超时回收，幂等可重入。不引入 MQ。
4. **向量检索 = Milvus（Standalone）**：混合检索（dense+BM25+RRF）；`project_id` 作 partition key，权限过滤按分区裁剪；重排留接口。
5. **切块策略**：结构化切块（Tika + LangChain4j），512-1024 token + 128 overlap；聊天按时间窗口切。
6. **流程编排 + 执行都在 Java**：JSON DAG 定义/审批/绑定/走查/执行一体；WASM 工作流远期。
7. **AI Agent + harness 在 Java**：LangChain4j/Spring AI function-calling；AI 新插件经注册中心 + Go 沙箱执行；工具调用落机械信号。
8. **飞书 I/O 全归 Go**：长连接收事件 + 开放 API 发消息；不做交互卡片，流程决策走管理端需求流程页（类似 OA）。
9. **密钥加密**：ssh key/IM secret/LLM key/Milvus key 落 `sec_secret`，AES-GCM 密文，明文不进库。
10. **多企业预留**：核心表带 `enterprise_id`。
11. **组织可观测性（留口子）**：直接聚合现有表出组织快照，独立可观测层二期。
12. **授权即边界（数据权限委托）**：`exec_task.authorizer_user_id` 记录授权人，AI 全链路（RAG/内容空间/git/IM/插件沙箱）限定在授权人作用域，越权拒绝并审计。
13. **越权审计（留口子）**：控制台"越权审计"页（人审）+ 观察器聚合越权统计（AI 审）；深度合规分析二期。
14. **接口即边界**：AI 不直连 Mapper/表，企业内容读取一律经带权限的「内容访问接口」；Go 插件沙箱为无凭据环境。
15. **定时任务 = Spring @Scheduled + Redis 分布式锁**：RAG 增量构建、任务超时回收、自举观察器周期审计统一用 `@Scheduled`，配 Redis 分布式锁（Redisson RLock，Redis 已存在、零新增中间件）保证多实例只有一个执行，不引入 Quartz/xxl-job/PowerJob 等调度中间件。

## 插件能力注册中心（简化 Nacos）

Go 沙箱加载 AI 写的插件后，需要一个注册中心让系统知道"怎么调、调用谁"。v0.1 做功能最简的 Nacos 类比物：

- **注册（控制面=Java，运行态=Go）**：审批、版本 ACTIVE 后，Java 经 `ActivatePlugin` 下发 {pluginKey, version, artifactRef, contractSchema} → Go 沙箱加载并写入 `boot_registry`；`DeactivatePlugin` 卸载/回滚。
- **契约（怎么调）**：每个插件声明 OpenAI function schema（name/description/parameters/output）+ 运行环境要求，存 `boot_plugin_version.contract_schema`，Java 为权威。
- **发现/路由（调用谁）**：按 `capabilityKey` 查找 → {pluginKey, activeVersion, contract}；同能力多版本按优先级取 ACTIVE，失效版本路由不到。
- **状态/一致性**：Go 上报 load_state + 心跳；`ListPlugins` 与控制面对比，控制台可见不一致。
- **调用**：Java agent 按契约暴露为 function-calling 工具 → LLM 选中 → `ExecutePlugin{pluginKey, version, args}` → Go 沙箱执行 → 流式回传。

## AI 自举（受控）：协作中发现 → 即写即执行 → 晋升审批

- **发现（多通道，v0.1 均最小实验）**：① **即时发现**——agent 干活中识别可复用模式 → `propose_plugin` 起草 DRAFT；② **周期发现——自举观察器**——定时聚合现有任务/流程/工具/审计数据 + 内容空间 RAG，输出观察报告 + 候选插件提案 → 审核转 DRAFT。**留口子**：观察器只做最简实现（@Scheduled + 一次 LLM 归纳 + observer_report 落库）。
- **harness 工具自省（留口子）**：v0.1 只落数据口子——工具调用机械信号记入 `exec_task_event`，预留 `tool_feedback` 字段；完整审视/版本升级提案放二期，复用审批/版本管线。
- **即写即执行（自举的自由）**：DRAFT 插件立即加载进 Go 沙箱**开发态**试运行，只碰沙箱资源、不接触生产。
- **晋升（自举的受控）**：试运行满意 → 审批（boot_approval）→ 版本 ACTIVE → `ActivatePlugin` 下发事件订阅 → 接收真实业务/IM 事件流量；回滚走 `DeactivatePlugin`。全程 audit_log。
- **业务型插件（飞书小服务）**：声明 `events` 订阅（IM 群消息命中、task 状态变更、flow 节点进入、文档新增）→ Java 域发领域事件 → gRPC 事件流 → Go 分发 → 插件执行并回发动作。工具型插件走 function-calling 契约。

## 关键注意点（风险清单）

- **并发安全**：任务领取/状态迁移必须单行条件 UPDATE（status=? 乐观锁）；执行幂等可重入。
- **契约漂移**：跨服务唯一契约 = gRPC .proto + schema.sql + 表所有权清单，改契约三处同步。
- **权限不可绕过**：AI 读企业内容只经「内容访问接口」，禁止注入 Mapper/直连表；Go 沙箱无凭据。
- **沙箱隔离**：Go 插件执行限定命令白名单/资源上限/超时；worker 独立容器；不注入生产凭据。
- **密钥安全**：ssh key/im secret/llm key 只存 sec_secret 密文（AES-GCM），明文不进库。
- **超时回收**：CLAIMED 带 claim_at+deadline，超时回收重置，避免死任务。
- **本地 dev 无公网**：飞书用长连接收事件；流程决策走管理端页面（无需公网回调）。
- **多企业预留**：核心表带 enterprise_id，v0.1 单企业部署但结构预留。
- **Milvus 运维权重**：Standalone 单机可跑，资源占用比 Qdrant 高，规模大了再上分布式。
